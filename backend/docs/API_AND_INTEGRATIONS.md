# API and Integrations Reference

## API conventions

The primary application API is GraphQL at `/graphql`. It is generated by GraphQL SPQR from annotated Groovy services; it is not maintained as a static schema file in this repository. Use authenticated schema introspection/GraphiQL in a safe local environment for exact field names, enum values, input shapes, and nullability.

### Authentication

| Action | Route | Contract |
| --- | --- | --- |
| Log in | `POST /api/authenticate` | Form-encoded `username` and `password`; establishes the HTTP session |
| Log out | `POST /api/logout` | Invalidates session and clears `JSESSIONID` |
| Current account | GraphQL `account` query | Used by the frontend after login to obtain identity, roles/access, office, and current company |

GraphQL/API clients must preserve the session cookie. Use the frontend’s Apollo/Axios setup as the reference client. Do not send credentials through GraphQL arguments or replace the existing cookie session with a feature-specific token scheme.

### GraphQL design

| Element | Convention |
| --- | --- |
| Service | Spring `@Component`, `@GraphQLApi` |
| Read | `@GraphQLQuery`, typically a list/entity/page/DTO |
| Write | `@GraphQLMutation`, often `GraphQLResVal<T>`/`GraphQLRetVal<T>` |
| Arguments | Named `@GraphQLArgument`s; UUID IDs and module enums are common |
| Write transaction | `@Transactional(rollbackFor = Exception.class)` for multi-record workflows |
| Authorization/scope | Current Spring principal, company context, roles/permissions, and service-level checks |

GraphQL service ownership:

| Module | Service directory | Key capabilities |
| --- | --- | --- |
| Shared administration | `graphqlservices/` | account/company, user/authority/permission/policy, office/position, notification |
| Accounting | `graphqlservices/accounting/` | ledger, journals, chart setup, AP, AR, disbursement, payment, tax, report layouts |
| Billing | `graphqlservices/billing/` | jobs, billing, billing items, customers, service categories, charge invoices |
| Cashier | `graphqlservices/cashier/` | terminals, shifts, payments, petty cash |
| HRM | `graphqlservices/hrm/` | employee, attendance, schedules, leave, allowances, events, salary rates |
| Payroll | `graphqlservices/payroll/` | payroll lifecycle, timekeeping, contributions, tax, loans, deductions, adjustments |
| Inventory | `graphqlservices/inventory/` | item/supplier master data, purchasing, receiving, inventory ledger, issuance, returns, adjustments |
| Projects | `graphqlservices/projects/` | project/cost/progress/update/material/worker/work-accomplishment workflows |
| Assets/fixed assets | `graphqlservices/assets/`, `fixed_asset/` | asset maintenance, vehicle usage, rental/job orders, fixed asset items |
| Service management | `graphqlservices/services/` | service and service-item setup |

For a change, find the existing service by module/feature name and inspect the live schema plus its frontend call site. Do not create an operation purely from this high-level index; its arguments and behavior may have evolved.

## REST route families

All `/api/**` and `/graphql/**` routes are authenticated by the current security configuration. Public and legacy exceptions are configuration-specific; do not rely on a route being public without checking `MultiHttpSecurityConfig`.

### Public and utility routes

`/public/**` includes utility endpoints such as password encoding, remote IP, and user information. `/user/**` and `/project/**` include legacy security exceptions. Their security posture is intentional/legacy and must not be expanded casually. Any change touching these routes needs explicit security review and current deployment validation.

## WebSocket/STOMP

The application exposes a SockJS STOMP endpoint at `/ws` with permissive allowed origins. Client-to-server destinations use `/app`; messages are brokered under `/channel`.

- If `mq.host` is empty, Spring’s in-memory/simple broker is used.
- If `mq.host` is configured, the app uses a STOMP broker relay on port 61613.
- `SocketController` and `SocketService` currently contain commented-out message-handler/send examples, so do not assume a working product event channel exists just because the endpoint is configured.

WebSocket use is currently permitted by HTTP security. New subscriptions/messages must still have a documented authorization and tenant strategy; broker destinations are not automatically a substitute for application authorization.

## SOAP

`SoapConfig` configures a `SOAPConnector` and JAXB marshalling. Generated/external SOAP types also exist under `src/main/java`. The REST utility resource contains a SOAP test route. Treat SOAP endpoint URLs, credentials, generated artifacts, and request/response contracts as external integration configuration—not values to copy into code or documentation. Add an adapter/service boundary rather than leaking SOAP details through unrelated GraphQL code.

## Object storage and multipart files

`DigitalOceanSpaceService` owns object-storage access. Multipart is enabled globally and the configured maximum file/request size is 50 MB. File endpoints must:

1. authenticate and authorize before accepting or revealing files;
2. tie the file to the correct business document and company;
3. validate filename/type/size according to the existing module policy;
4. handle storage failure without persisting a misleading document state; and
5. avoid returning sensitive storage credentials or broadly reusable URLs.

## API change checklist

1. Identify the existing service/resource owner and its frontend caller.
2. Preserve session auth, company scope, role/permission checks, and status rules.
3. Use GraphQL for standard business data; use REST only for an HTTP-specific need.
4. Keep read/write contract naming and response styles consistent with the module.
5. Make related writes transactional and validate failure/rollback.
6. Regenerate frontend GraphQL types for schema changes.
7. Exercise successful, unauthorized, wrong-company, invalid-input, and invalid-state paths locally.
